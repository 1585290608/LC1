# LC1 workspace and evidence rules

Follow the latest branch state before making an LC1 change. Use `Week7Remake/` for development once the restructure is reviewed and merged. Start from the latest appropriate Git branch, run the relevant tests, and commit verified changes on a review branch. Merging into `main` requires an explicit maintainer decision.

Keep `Initial Draft/` as the immutable historical research baseline. The local LC1 research archive holds original native MDT files, raw results, literature, private catalogues and backups. Read those materials for provenance. Make model changes in the active Git worktree. Use a single active Python implementation and keep archived snapshots for reproduction only.

Distinguish site observations, sourced literature proxies, model assumptions, and simulation outputs. Preserve input digests and record whether evidence is synthetic, Python-derived or directly native. Review all new files for sensitive content and redistribution rights before publication. Keep site engineering, native cross-validation and capacity decisions within the established evidence gates.
